## 角色

你是一名资深 Windows 桌面应用工程师，接手一个已在运行的 Python 项目做**增量改造**。你的首要原则是**不破坏现有算法能力**：这个工具的核心价值在 `wmremove/temporal.py`、`methods.py`、`colorfit.py` 里的图像处理实现，本次任务一行算法逻辑都不要重写，只做产品层与编排层的重构。任何"顺手优化算法"的冲动都要压制，先问我。

## 项目事实（已核实，不要再自行猜测或重新审计）

- 路径：`D:\HuaweiMoveData\Users\liuho\Desktop\WatermarkRemover`
- 技术栈：Python 3.13 + numpy + opencv-python + Pillow + imageio-ffmpeg（内置 ffmpeg）+ tkinter；可选 yt-dlp
- 规模：`wmremove/` 10 个模块，约 5,300 行；另 tests 与 packaging 约 1,600 行
- 模块职责：
  - `main.py` 统一入口，无参数时进 GUI
  - `wmremove/cli.py` 六个子命令 `remove/detect/download/batch/gui/selftest`，40+ 参数
  - `wmremove/gui.py` 单个 `App` 类，950 行，1280×860 固定三栏
  - `wmremove/engine.py` 掩码构建 + 时序方案选择 + 编码调度 + 质量报告（四个职责混在一个模块）
  - `wmremove/temporal.py` 淡入层配对 / 仿射分离 / 静态层替换（**核心算法，禁止改动**）
  - `wmremove/methods.py` 11 种空间修复 + auto 选路（**核心算法，禁止改动**）
  - `wmremove/colorfit.py` 低频对齐 / 颗粒 / 接缝自检（**核心算法，禁止改动**）
  - `wmremove/detect.py` 19 组平台位置先验（`KNOWN` 常量硬编码）+ 内容分析紧致化
  - `wmremove/shapes.py` 区域形状与羽化
  - `wmremove/media.py` ffmpeg 定位、探测、逐帧管道编码
  - `wmremove/downloader.py` 1,060 行站点解析（**本次不要碰**）
  - `tests/selftest.py` 合成真值 PSNR 自测；`tests/regression.py` 多平台抽帧对比
  - `packaging/` 自研 Tk 安装器 + 独立卸载器，打包产物 102 MB
- 现状问题（本次要解决的）：
  1. 参数过早暴露：首屏 4 个数值输入 + 3 个开关 + 7 项算法下拉
  2. 结果不可自证：预览只渲单帧，质量以「色差 3.21 / 台阶 0.84」这类开发者指标输出
  3. 失败无归因：异常统一 `messagebox.showerror("处理失败", str(e))`
  4. 无拖拽导入、无撤销、无处理取消、无批量 GUI
  5. Git 仓库 **0 个提交**，没有版本追溯

## 本轮目标（v1.1，主题：一键可信）

让一个没看过说明书的人，把视频拖进窗口后 **3 次点击内出片**，并且能自己判断"这结果行不行"。

必须交付的 7 条需求：

| 编号 | 需求 | 验收 |
|---|---|---|
| R-01 | 拖拽文件/文件夹到窗口即导入 | 拖入 100 MB mp4 到可操作状态 ≤ 1.5 s |
| R-02 | 一键去水印：自动定位 + 自动选算法 + 自动质量自检，默认路径无任何参数控件 | 导入到出片 ≤ 3 次点击 |
| R-03 | 结果对比：原片/成片同步对比 + 滑动分割 + 1:1 放大平移 | 可定位任意时间点 |
| R-04 | 质量小结：三档结论（过渡自然/边缘略生硬/可能留有痕迹）+ 位置提示 | 文案与固定阈值一一对应，多次运行结论一致 |
| R-05 | 失败归因四类 + 「再试一次」 | 四类均可由现有指标触发；重试不需重新框选 |
| R-13 | 首次引导：三步说明 + 本地处理声明 + 内容权利提示 | 10 秒可读完；关闭后不再弹 |
| R-15 | 工程基线：Git 提交与 tag、参数集中、服务层拆分起步 | 发版有 tag；界面层不含算法分支 |

**本轮明确不做**：多语言、自动更新、账号、云端处理、批量队列（v1.2）、下载模块改造（v1.3）、更换 GUI 框架、打包流程改动。

## 硬约束（违反任何一条请停下来问我）

1. `temporal.py` / `methods.py` / `colorfit.py` 的函数实现不改；如确需调整默认参数，只在 `engine.Options` 或新增配置里改，并说明理由。
2. CLI 六个子命令与现有参数必须向后兼容——已有的命令行脚本不能因为 GUI 改造而失效。
3. 不引入重型依赖。拖拽实现二选一：`windnd` 或 `tkdnd`，先告诉我你选哪个、为什么、打包会不会出问题；我不同意就降级为"大按钮 + 拖入提示"。
4. 不联网、不上传、不加遥测。除用户主动点「检查更新」（本轮不做）外不得发网络请求。
5. 不换 GUI 框架（不引入 PyQt/PySide/Electron/WebView）。
6. 不删除 `downloader.py`、`packaging/`、`dist/` 的任何内容，也不要把 `dist/` `build/` `__pycache__/` 提交进仓库。
7. 不做一次性大重构。`gui.py` 允许变厚也允许拆文件，但**每一步都要能跑起来**，不能中途留半成品状态。

## 实施步骤（一步一验收，每步做完停下来等我确认）

**Step 0 · 基线**
- 初始化提交：把现有代码全部提交，打 `v1.0.0` tag，配 `.gitignore`（`dist/ build/ __pycache__/ *.pyc`）
- 写一个 `tests/bench.py`：读桌面 `去水印测试结果/1–4.mp4`，逐个跑一遍现有管线，输出耗时、采用方案、各项质量指标的 CSV
- 产出：基线数据表（我要用它当后续所有"变快了/变差了"的对照）

**Step 1 · 服务层抽取（不动界面）**
- 新增 `wmremove/services/task.py`：`TaskService`，负责 导入 → 定位 → 处理 → 评估 → 导出 的编排，对外只暴露 `run(task, on_progress) -> QualityReport`
- 新增 `wmremove/services/quality.py`：`QualityService`，把 `colorfit.report` + 时序统计 + 紧致化统计汇总成 `QualityReport`，含：三档结论、归因标签、风险帧列表、采用的方案名
- 新增 `wmremove/config.py`：读写 `%LOCALAPPDATA%\WatermarkRemover\config.json`（输出目录、命名规则、质量档、并发=1、可选模块开关）
- 要求：`cli.py` 与 `gui.py` 都改为调用这层；行为与改造前**完全一致**（用 Step 0 的基线逐项比对）
- 验收：`python main.py selftest` 全绿；`python main.py remove -i 1.mp4 --auto` 输出与改造前一致

**Step 2 · 工作台首页 + 拖拽导入**
- 新增首页视图：中央拖入区 + 一句「拖入视频或图片，其余交给我们」+ 副行「全部在本机处理，不上传」+ 底部「仅处理你拥有权利的内容」
- 最近任务列表（本地记录，缩略图可关闭、可一键清除）
- 一个页面容器负责首页/编辑/结果三视图切换，不要再用一个大 Frame 全塞
- 验收：拖入即进入编辑视图；无文件时拖入文件夹可入队（队列 UI 本轮可暂缺，先提示"v1.2 支持"）

**Step 3 · 编辑页收敛**
- 默认工具改为「选择」而非「矩形」；区域支持拖拽移动、四角缩放、Delete 删除、Ctrl+Z 撤销（自己维护一个操作栈，不要引入依赖）
- 右侧参数面板整体折叠进「高级设置」，默认收起；每个参数右侧加一行浅灰说明
- 顶部显示当前判断，例如「检测到：右下角半透明角标（淡入）」
- 验收：全新用户不看任何说明，能找到并点击「开始处理」；高级设置展开后所有既有参数仍可达

**Step 4 · 结果页（本轮重心）**
- 对比视图：沿时间轴抽 5–9 帧，左右并排 + 可拖动分割线 + 1:1 放大平移（**零新依赖方案**，连续播放留到 v1.2）
- 风险时间轴：把逐帧接缝比映射为黄/红刻度，点击跳到该帧
- 质量小结卡：三档结论 + 一句话原因 + 建议动作按钮
- 主按钮「导出」写入配置目录不弹框；次按钮「再试一次（更强）」「再试一次（更保守）」，复用区域与文件，只切策略，不重跑检测
- 归因映射按 `v1.1-需求清单.md` 第二节的四类实现，触发信号优先复用 `QualityReport` 里已有字段
- 验收：对 1–4.mp4 各跑一次，四类归因至少能真实触发两类；点击「再试一次」全程不出现框选界面

**Step 5 · 引导与合规**
- 首次启动三步引导（一次性，可跳过，可回看）
- 设置页加「隐私与合规」区块：本地处理说明、日志清除、诊断日志导出（本地文件，不自动上传）
- 验收：断网全流程可用；引导关闭后不再出现

**Step 6 · 回归与收口**
- 跑 `tests/selftest.py` + `tests/bench.py`，与 Step 0 基线逐项对比，输出差异表
- 检查 Windows 150% 缩放下界面不模糊、不重叠
- 更新 `README.md` 的"快速上手"为新的三步流程（保留 CLI 章节）
