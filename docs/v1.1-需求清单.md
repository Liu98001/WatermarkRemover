# WatermarkRemover v1.1 需求清单（可开工版）

> 摘自 `产品重设计方案-v1.html` 第 4 / 7 / 11 节，供拆分任务直接使用。若与本清单有出入，以 HTML 设计稿为准。
> 版本主题：**一键可信**——3 次点击出片，结果能自证，失败能解释。

---

## 一、范围（v1.1 只做这 7 条）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| R-01 | 拖拽文件/文件夹到窗口即导入 | Must | 拖入 100 MB mp4 到可操作 ≤ 1.5 s |
| R-02 | 一键去水印（自动定位 + 自动选算法 + 自动自检） | Must | 导入到出片 ≤ 3 次点击；默认路径不出现技术参数控件 |
| R-03 | 结果对比（同步对比 + 分区滑动 + 1:1 放大） | Must | 可定位任意时间点；1:1 模式可平移查看 |
| R-04 | 质量小结（三档结论 + 位置提示） | Must | 每档文案对应固定阈值，多次运行结论一致 |
| R-05 | 失败归因四类 + 「再试一次」 | Must | 四类均可由现有指标触发；重试不需重新框选 |
| R-13 | 首次引导（三步说明 + 本地处理声明 + 权利提示） | Must | 10 秒可读完；关闭后不再弹 |
| R-15 | 工程基线（Git 提交/tag、参数集中、服务层拆分起步） | Must | 发版有 tag；界面层不含算法分支 |

**v1.1 明确不做**：多语言、自动更新、账号体系、云端处理、批量队列（v1.2）、下载模块改造（v1.3）。

## 二、失败归因四类（R-05 的实现依据）

内部信号已存在于代码，只需暴露与映射：

| 归因标签 | 触发信号 | 建议动作（按钮） | 用户文案 |
|---|---|---|---|
| 贴片不透明 | `build_mask` 不透明域判定触发 / 接缝比 > 2.5 | 「改用覆盖式处理」 | 「这块水印是不透明的，像素级还原会留边，建议整块覆盖」 |
| 背景持续运动 | `_stable_windows` 无稳定窗 / 时序覆盖率 < 50% | 「改用逐帧修复」 | 「画面一直在动，没有干净参考，换成逐帧修复更稳」 |
| 水印超出框选 | `plan.repl` 非空 / 笔画延续并入量超阈值 | 「自动扩大范围」 | 「水印比框选范围大，我帮你扩了一点」 |
| 画面活动过大 | `_choose_spatial_mode` 判为逐帧且注入门控频繁触发 | 「分段处理」 | 「这一段变化太大，建议分段处理」 |

## 三、质量文案阈值（R-04 的实现依据）

| 指标 | 通过 | 注意 | 警示 |
|---|---|---|---|
| 边界台阶 `seam_step` | < 1.5 → 过渡自然 | 1.5–2.5 → 边缘略生硬 | > 2.5 → 可能留有痕迹 |
| 区域-环色差 | < 6 → 色温一致 | 6–10 | > 10 |
| 时序覆盖率 | — | < 50% → 难分离 | 0（未启用） |
| 紧致化覆盖 | — | < 15% → 按整块处理 | — |

## 四、技术拆分建议（顺序即依赖）

1. **服务层抽出**（先做，否则后面全在改巨石）
   - `TaskService`：导入 → 定位 → 处理 → 评估 → 导出 的编排，GUI 只调用它、只收进度回调
   - `QualityService`：把 `colorfit.report` + 时序统计 + 紧致化统计汇总为一个 `QualityReport` 结构（含三档结论与归因标签）
   - `Settings`：输出目录/命名/质量/性能/可选模块，落 `config.json`
2. **拖拽导入**：`tkdnd` 需额外依赖，替代方案是 `windnd`（轻量）或自绘不可行；若不想加依赖，先做"打开文件"大按钮 + 首屏拖入提示（降级实现）
3. **对比视图**：先做"抽帧步进"（沿时间轴抽 5–9 帧，左右并排/滑动分割），零新依赖；连续播放放 v1.2
4. **质量小结 + 归因**：纯前端渲染 `QualityReport`，无算法改动
5. **再试一次**：复用同一区域与文件，只切策略（`static_fill` / `temporal` / `method` 三档预设），不重跑检测
